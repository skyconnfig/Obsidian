# Windows Server 2016 软件部署全流程（含IIS、SQL Server及应用配置）

以下是基于Windows Server 2016系统的软件标准化部署流程，涵盖服务器环境搭建、数据库配置、应用安装及网络权限设置，步骤清晰且包含关键操作要点：

## 1. 安装IIS服务器（Web服务基础环境）

### 操作步骤：

1. 打开 **服务器管理器** → 点击左侧「管理」→ 选择「添加角色和功能」；
2. 在「添加角色和功能向导」中，依次点击「下一步」，直至「服务器角色」页面；
3. 勾选「Web服务器(IIS)」，弹出「添加角色和功能所需的功能」对话框时，点击「添加功能」；
4. 进入「角色服务」页面，勾选核心组件（必选：Web服务器、ASP.NET 4.6+、.NET扩展性、ISAPI筛选器；可选：HTTP重定向、日志记录工具）；
5. 后续步骤保持默认配置，点击「安装」，等待安装完成后重启服务器（可选，建议重启以确保组件生效）。

### 关键要点：

* 若应用依赖旧版ASP.NET（如ASP.NET 3.5），需在「功能」页面额外勾选「.NET Framework 3.5功能」；
* 安装后可通过访问 `http://localhost` 验证IIS是否正常（显示默认IIS欢迎页即成功）。

## 2. 安装SQL Server 2016数据库

### 操作步骤：

1. 挂载SQL Server 2016安装光盘（或加载ISO镜像），运行根目录下的 `setup.exe`；
2. 在「SQL Server安装中心」点击「安装」→ 选择「全新SQL Server独立安装或向现有安装添加功能」；
3. 产品密钥验证：输入正版密钥（或选择「指定免费版本」→「Express」，若为轻量应用）；
4. 接受许可条款，跳过「产品更新」（建议后续手动更新），进入「功能选择」页面；
   * 必选：数据库引擎服务、SQL Server复制、客户端工具连接（SSMS）；
   * 可选：全文和语义提取搜索（需全文检索时勾选）；
5. 「实例配置」：选择「默认实例」（推荐，便于后续管理）或自定义实例名（需记录，后续连接需用）；
6. 「服务器配置」：服务账户建议使用「NT AUTHORITY\NETWORK SERVICE」（默认），启动类型设为「自动」；
7. 「数据库引擎配置」：
   * 身份验证模式：勾选「混合模式」，设置 `sa` 账户密码（复杂度需符合要求：含大小写、数字、特殊字符）；
   * 指定SQL Server管理员：点击「添加当前用户」（或手动添加服务器管理员账户）；
8. 后续步骤保持默认，点击「安装」，等待完成后重启服务器。

### 关键要点：

* 安装后需验证数据库服务：打开「服务」→ 确认「SQL Server (MSSQLSERVER)」状态为「正在运行」；
* 建议立即安装SQL Server最新补丁（通过Windows Update或微软官网下载），修复安全漏洞。

## 3. 安装.NET运行环境（匹配应用依赖）

### 操作步骤：

1. 确认应用所需.NET版本（常见为.NET Framework 4.5/4.6/4.8，或.NET Core 3.1/6.0）；
2. **方式1：通过服务器管理器安装（.NET Framework）**
   * 打开「服务器管理器」→「添加角色和功能」→ 「功能」页面；
   * 勾选对应版本的「.NET Framework 功能」（如.NET Framework 4.8），点击「安装」；
3. **方式2：手动安装（.NET Core/.NET 5+）**
   * 从微软官网下载对应版本的.NET Runtime（<https://dotnet.microsoft.com/download）；>
   * 运行安装程序，按向导完成安装，无需额外配置。

### 关键要点：

* 若IIS已安装对应.NET组件，可跳过重复安装；通过「IIS管理器」→「应用程序池」→ 查看「.NET CLR版本」，确认是否匹配应用需求。

## 4. 安装业务软件（通过提供的光盘介质）

### 操作步骤：

1. 挂载软件安装光盘（或复制光盘内所有文件至服务器本地目录，避免光盘读取不稳定）；
2. 找到安装程序（通常为 `Setup.exe` 或 `Install.exe`，若有「安装说明.doc」需优先查看）；
3. 右键点击安装程序 → 选择「以管理员身份运行」（避免权限不足导致安装失败）；
4. 按安装向导提示操作：
   * 安装路径：建议选择非系统盘（如 `D:\Program Files\应用名称`），避免占用C盘空间；
   * 组件选择：勾选所有必要组件（如客户端、服务端、配置工具）；
   * 快捷方式：按需创建桌面/开始菜单快捷方式；
5. 安装完成后，暂不启动应用（待数据库还原、站点配置完成后再测试）。

### 关键要点：

* 若安装过程中提示「缺少XX组件」，需先安装对应依赖（如VC++ Redistributable、Java Runtime等，通常光盘会附带）；
* 记录安装路径（后续配置站点时需指定网站根目录）。

## 5. 还原业务数据库（SQL Server数据导入）

### 操作步骤：

1. 准备数据库备份文件：从光盘或指定路径找到数据库备份（通常为 `.bak` 格式），复制至服务器本地（如 `D:\SQL_Backup`）；
2. 打开「SQL Server Management Studio (SSMS)」：
   * 服务器名称：输入 `localhost` 或 `./MSSQLSERVER`（默认实例）；
   * 身份验证：选择「SQL Server身份验证」，输入 `sa` 账户和密码，点击「连接」；
3. 还原数据库：
   * 右键点击「数据库」→ 选择「还原数据库」；
   * 「源」选择「设备」→ 点击「...」→ 「添加」→ 选择备份文件（.bak）→ 点击「确定」；
   * 「目标」确认数据库名称（需与应用配置一致，如 `BusinessDB`）；
   * 点击「选项」页面，勾选「覆盖现有数据库」（若为新部署，此步骤可选）；
   * 点击「确定」，等待还原完成（提示「还原成功」即结束）。

### 关键要点：

* 若还原失败，检查备份文件完整性（是否损坏）、数据库权限（`sa` 账户是否有「还原」权限）；
* 还原后建议验证数据：右键点击数据库 →「新建查询」，执行简单查询（如 `SELECT * FROM dbo.用户表`），确认数据正常。

## 6. 配置IIS站点（关联业务软件目录）

### 操作步骤：

1. 打开「IIS管理器」（通过「服务器管理器」→「工具」→「Internet Information Services (IIS)管理器」）；
2. 新建网站：
   * 右键点击左侧「服务器名称」→「网站」→「添加网站」；
   * 填写站点信息：
     * 网站名称：自定义（如「业务系统站点」，便于识别）；
     * 物理路径：点击「浏览」→ 选择业务软件的网站根目录（通常在软件安装路径下的 `Web` 或 `WWWROOT` 文件夹）；
     * 应用程序池：默认自动创建，或手动选择匹配.NET版本的应用程序池（如「.NET CLR版本 v4.0」）；
   * 点击「确定」，站点创建完成。

### 关键要点：

* 配置站点权限：右键点击站点物理路径 →「属性」→「安全」→ 给「IIS\_IUSRS」账户添加「读取&执行」「列出文件夹内容」「读取」权限（避免访问时提示403权限不足）。

## 7. 绑定站点IP与端口 + 放通Windows防火墙端口

### 操作步骤：

#### 步骤7.1：绑定站点IP和端口

1. 在「IIS管理器」中，选中新建的站点 → 点击右侧「编辑绑定」；
2. 点击「添加」→ 配置绑定信息：
   * 类型：默认「http」（若需HTTPS，需先申请SSL证书）；
   * IP地址：选择服务器的实际IP（如 `192.168.1.100`，避免选择「全部未分配」，确保外部可访问）；
   * 端口：自定义端口（如 `80` 为HTTP默认端口，若80被占用可改为 `8080`「8081」，需记录端口号）；
   * 主机名：若需通过域名访问，填写域名（如 `system.example.com`，无需域名则留空）；
3. 点击「确定」→「关闭」，绑定完成。

#### 步骤7.2：放通Windows防火墙端口

1. 打开「控制面板」→「系统和安全」→「Windows Defender防火墙」→「高级设置」；
2. 左侧选择「入站规则」→ 右侧点击「新建规则」；
3. 规则类型：选择「端口」→「下一步」；
4. 协议和端口：
   * 协议：选择「TCP」；
   * 特定本地端口：输入步骤7.1中绑定的端口（如 `8080`，多个端口用逗号分隔）；
5. 操作：选择「允许连接」→「下一步」；
6. 配置文件：勾选「域」「专用」「公用」（根据服务器网络环境选择，建议全勾选）→「下一步」；
7. 名称：自定义规则名称（如「业务系统8080端口」）→「完成」。

### 关键要点：

* 端口绑定后需验证：在服务器本地打开浏览器，访问 `http://绑定的IP:端口`（如 `http://192.168.1.100:8080`），确认能正常打开应用登录页；
* 若服务器部署在局域网，需确保客户端与服务器网络互通（通过 `ping 服务器IP` 验证）。

## 8. 部署后验证（确保全流程可用）

1. 本地验证：服务器本地访问站点，测试登录、核心功能（如数据查询、表单提交）是否正常；
2. 远程验证：从客户端电脑访问 `http://服务器IP:端口`，验证远程访问是否正常；
3. 数据库连接验证：在应用配置文件（通常为 `Web.config` 或 `appsettings.json`）中，确认数据库连接字符串是否正确（如 `Data Source=localhost;Initial Catalog=BusinessDB;User ID=sa;Password=XXX`）。
