# 信息安全方案

## **<font style="color:rgb(0,0,0);">1、系统安全设计要点</font>**
**<font style="color:rgb(0,0,0);">网络隔离与访问控制：</font>**采用Windows防火墙策略，通过高级设置配置入站规则，仅开放必要的业务端口,系统部署采用cs层次架构设计：实现业务功能隔离,严格限制访问范围，仅允许内网或指定IP地址访问.

**<font style="color:rgb(0,0,0);">服务器安全加固：</font>**

基于Windows Server 2016操作系统，定期安装安全补丁,禁用不必要的系统服务和端口，减少攻击面,配置IIS应用程序池隔离机制，session配置优化，启用32位应用程序设置，确保应用程序稳定运行，限制IIS日志文件目录访问权限，仅授权管理员账户可访问。

**<font style="color:rgb(0,0,0);">数据库安全机制：</font>**

采用SQL Server 2016数据库，配置混合身份验证模式，强化认证安全性

严格控制数据库用户权限，遵循最小权限原则分配访问权限。

数据库存放于自定义目录，设置严格访问控制列表(ACL)

通过SQL Server Agent服务实现自动化备份，确保数据可恢复性。



**<font style="color:rgb(0,0,0);">应用层安全设计：</font>**

**<font style="color:rgb(0,0,0);">采用</font>****<font style="color:rgb(0,0,0);">ASP.NET 框架开发，利用框架内置的安全机制防止常见Web</font>****<font style="color:rgb(0,0,0);">攻击</font>**

实现严格的输入验证和输出编码，防范XSS、SQL注入等攻击

管理员页面采用强密码策略和登录失败锁定机制

敏感操作记录审计日志，便于追踪和分析

数据生命周期安全管理：

建立定期备份机制，通过SQL Server维护计划实现数据库自动备份

配置备份数据定期清除策略，保留最近4天的备份数据

实现数据库日志定期清理机制，控制日志文件大小并保护存储空间

提供数据清除脚本，支持敏感数据安全擦除

## <font style="color:rgb(0,0,0);">2. </font><font style="color:rgb(0,0,0);">系统数据传输加解密方式</font>
为保障系统数据传输安全，采用以下加密机制：

**<font style="color:rgb(0,0,0);">传输层加密：</font>**

建议配置HTTPS协议，通过IIS管理器为各站点配置SSL证书，**<font style="color:rgb(0,0,0);">确</font>**保所有数据传输使用TLS 1.2或更高版本加密

配置SSL绑定，强制使用加密通道通信

禁用不安全的加密协议(SSLv2/SSLv3)和弱加密算法，仅允许使用AES等强加密算法

**<font style="color:rgb(0,0,0);">数据传输安全：</font>**

服务采用基于Token的身份验证机制，Token使用JWT标准并设置合理有效期

数据库连接加密：

数据库连接字符串存储于各应用的web.config配置文件中，建议使用进行加密

配置SQL Server启用"强制加密"选项，确保客户端与数据库服务器间通信全程加密

数据库连接密码不以明文形式存储，采用加密存储方式

**<font style="color:rgb(0,0,0);">敏感数据传输保护：</font>**

用户密码等敏感信息在传输前进行单向哈希处理，系统端存储哈希值而非原始密码

关键业务数据传输采用AES-256对称加密算法进行端到端加密

实现数据完整性校验机制，使用HMAC-SHA256算法确保传输数据未被篡改。



## <font style="color:rgb(0,0,0);">3.</font><font style="color:rgb(0,0,0);"> </font><font style="color:rgb(0,0,0);">对客户信息等敏感数据保护方案</font>


**<font style="color:rgb(0,0,0);">针对系统中存储的客户信息等敏感数据，实施全方位保护措施：</font>**

**<font style="color:rgb(0,0,0);">数据存储加密：</font>**

对数据库中存储的敏感信息（如用户密码、个人信息等）实施列级加密

采用SQL Server 2016的Always Encrypted功能，确保敏感数据在客户端加密、服务端解密

访问控制与权限管理：

**<font style="color:rgb(0,0,0);">实施严格的基于角色的访问控制</font>****<font style="color:rgb(0,0,0);">(RBAC)，不同角色仅能访问授权</font>****<font style="color:rgb(0,0,0);">范围内的数据</font>**

数据库访问仅限于应用程序账户，禁止直接使用sa账户连接，用不同数据库用户连接。

实现细粒度的数据访问审计，记录所有敏感数据的访问行为

数据脱敏与隐私保护：

实训和考试数据中的敏感信息在展示前进行匿名化处理

严格控制数据权限，导出操作需经审批并记录日志

数据安全清理机制：

实施定期数据清理策略，使用文档中提供的清除数据库脚本安全删除过期用户数据

数据库日志清理采用安全删除方式，防止数据恢复



**<font style="color:rgb(0,0,0);">安全监控与应急响应：</font>**

部署数据库活动监控工具，实时检测异常查询行为

建立敏感数据访问异常告警机制，及时发现潜在数据泄露风险

制定完善的数据泄露应急预案，包括事件响应流程和通知机制

定期进行安全漏洞扫描和渗透测试，持续改进数据保护措施
