# 一、产品定位与教学价值
本软件是专为大学金融类专业（金融学、金融工程、投资学等）研发的沉浸式理财规划教学实训平台，基于.NET Framework 技术栈构建，核心目标是解决金融专业教学中“理论教学多、实践操作少”“案例单一、与真实业务脱节” 的痛点。平台以“模拟真实金融场景、贴合课程教学目标” 为核心，采用模块化设计， 1:1 还原银行、券商、第三方理财机构的理财业务全流程，覆盖“客户信息采集

→财务状况分析→风险偏好评估→理财目标设定→产品组合配置→规划方案生成与优化”  六大核心环节，助力教师开展“场景化实训教学”，帮助学生将《个人理财规划》《金融风险管理》《投资学》等课程的理论知识转化为实操能力，为毕业后进入金融行业从事理财顾问、投资分析等岗位奠定实践基础。

## 2.2 物理部署架构：适配学校实验室环境
考虑到学校实验室服务器资源、网络环境特点，部署方案采用“轻量化、易维护、可扩展” 设计，无需学校额外投入复杂硬件：



Web 服务器：基于IIS 10.0 部署，支持按“课程/ 班级” 配置独立应用程

  


序池（如“2024 级金融学1 班实训池”“《投资学》课程实训池”），避免不同

班级实训数据冲突；通过负载均衡技术，支持至少500 名学生同时在线开展实训，满足学校“多班级集中实训” 需求。

数据库服务器：采用SQL Server 2019 Always On 高可用组，主服务器故障时备用服务器可秒级切换，保障实训课程不中断；支持按“学期” 自动归档历史实训数据（如2023-2024 学年实训数据归档至历史库），减少当前数据库负载，提升查询速度。

缓存服务器：Redis Cluster 集群部署，缓存实训常用数据（如“模拟客户基础信息”“标准化金融产品参数”“实训任务说明文档”），学生操作时无需反复加载数据，提升实训流畅度。

文件服务器：分布式文件存储系统，专门存储“教师上传的教学资源”（实训案例PPT、操作视频教程） 和“ 学生提交的实训成果”（理财规划报告 Word/PDF、方案演示PPT），支持按“课程- 班级- 学生- 实训任务” 分级管理，教师可快速定位并批改学生成果。

# 三、核心模块设计（教学功能强化版）


## 3.1 统一身份认证模块：贴合学校角色管理需求
针对学校“管理员- 教师- 学生” 三级教学角色体系，模块设计聚焦“权限清晰、操作简单”，无需与学校现有系统对接，独立实现高效身份管理：



角色权限定制：

管理员：拥有“账号管理（创建/ 删除教师/ 学生账号）、系统配置（设置实训并发量、数据归档周期）、数据备份” 权限，可按“专业/ 年级” 批量创建学生账号（如一次性创建2024 级金融工程专业100 名学生账号）；

教师：拥有“课程管理、实训任务创建、学生进度监控、成绩批改、案例上传” 权限，仅能查看和管理所授课程的学生数据，保障数据隔离；

学生：仅拥有“查看个人实训任务、提交实训方案、查询成绩与反馈” 权限，避免越权操作。

账号便捷管理：支持管理员导出账号清单（含账号、初始密码），教师可批量导入学生名单（Excel 格式），学生首次登录后强制修改初始密码，保障账号安全。

  


会话与登录管理：支持“单点登录+ 自动会话保存”，学生登录后可同时访问实训操作界面、教学知识库，无需重复输入账号密码；若学生中途离开，系统自动保存会话状态（最长2 小时），返回后可继续完成实训。



## 3.2 财务计算引擎：衔接课程理论与实训操作
引擎内置金融专业核心计算算法，既是学生的“实训工具”，也是教师的“教学辅助工具”，深度贴合课程教学重点：



核心算法覆盖课程知识点：



| <br/>算法功能 | <br/>对应课程章节 | <br/>教学应用场景 |
| :--- | --- | --- |
| <br/><br/>复利计算 | 《财务管理》“资金时间价值” | <br/>学生输入“本金、年利率、期限”，系统输出复利终值+计算步骤（如公式推导“F=P×(1+i)^n”），教师可结合结果讲解“复利对长期理财的影响”； |
| <br/><br/>年金计算 | 《个人理财规划》“退休规划” | <br/>模拟“学生为客户设计退休储蓄计划”，输入“退休目标金额、预期利率、储蓄期限”，系统计算每月需存入金额，帮助学生理解年金在退休规划中的应用； |
| <br/>内部收益率<br/>（IRR）计算 | 《投资学》 “ 项目投资评估” | 提供“模拟投资项目现金流量数据”，学生调用IRR 算法评估项目可行性，教师可对比不同项目的IRR 结果，开展“项目筛选” 专题教学； |
| <br/>风险价值<br/>（VaR）计算 | 《金融风险管理》“市场风险度量” | 学生为模拟投资组合（含股票、债券、基金）计算VaR值（支持95%/99% 置信水平），系统输出“每日VaR值+ 风险预警”，帮助学生理解风险度量逻辑。 |




自定义计算练习：教师可创建“计算专项练习”（如“复利计算10 道练习题”），设置练习时长和评分标准，学生完成后系统自动批改并展示错题解析，帮助学生巩固薄弱知识点。



## 3.3 规则引擎集成：灵活适配不同教学实训场景
规则引擎是实现“实训场景多样化” 的核心，教师可根据教学目标配置不同难度的实训规则，无需技术开发：

  


基础教学场景（入门级）：配置简单规则，用于大一/ 大二学生入门实训，帮助理解核心逻辑。例如：

规则条件：客户年龄> 60 岁+ 风险承受等级=“低”；

规则结果：自动标记客户风险profile=“高风险”，推荐“保守型产品组合”

（如存款+ 国债占比≥80%）；

教学应用：教师引导学生分析“为何年龄大、风险承受低的客户需推荐保守型组合”，理解风险与客户特征的匹配逻辑。

进阶教学场景（综合型）：增加规则复杂度，用于大三/ 大四学生综合实训，培养多因素分析能力。例如：

规则条件：客户年龄> 60 岁+ 风险承受等级=“低” + 有房贷负债（月供占收入比> 30%）+ 应急资金< 6 个月生活费；

规则结果：标记客户风险profile=“极高风险”，推荐“超低风险组合”（存款

+ 货币基金占比≥90%），并强制要求“优先配置3-6 个月应急资金”；

教学应用：教师布置“为多特征客户设计方案” 的实训任务，学生需考虑负债、应急资金等多因素，系统通过规则引擎自动校验方案合规性，不合规则提示原因（如“未配置应急资金，不符合客户风险特征”）。

规则可视化配置：教师通过“规则配置界面”（无需编写代码），拖拽“条件项”（如客户年龄、风险等级、负债情况）、设置“条件关系”（且/ 或）、选择“结果项”（推荐产品类型、风险标记），配置完成后即时生效，支持预览规则效果（如输入模拟客户数据，查看规则是否正确触发）。



## 3.4 智能客户管理模块：模拟真实客户服务场景
模块聚焦“让学生学会挖掘客户需求、分析客户特征”，提供丰富的模拟客户数据与分析工具，贴合理财顾问真实工作流程：



客户视图：为每个模拟客户提供“基础信息（年龄、职业、收入）+ 财务状况（资产负债、收支情况）+ 风险特征（风险承受等级、投资期限）+ 理财目标（购房、教育、退休）” 全维度数据，帮助快速掌握客户情况。

客户生命周期阶段识别：系统自动根据客户年龄、家庭状况、理财目标，标记客户生命周期阶段（如“青年期：单身，目标购房；中年期：已婚有子女，目标子女教育+ 退休”），教师可引导学生“按生命周期阶段设计差异化方案”，培养场景化服务思维。

  


客户价值分析：提供“客户价值评分模型”（基于收入、资产规模、潜在理财需求），学生可分析客户“短期/ 长期理财需求”，教师可布置“为高价值客户设计综合理财方案” 的实训任务，模拟真实职场中“客户分层服务” 场景。





# 四、数据库设计方案（教学数据管理优化）


## 4.1 数据库架构原则：适配教学数据特点
数据库设计遵循“教学数据分类存储、易统计、可归档、高安全” 原则，无需依赖学校其他系统，独立实现教学数据管理：



领域驱动设计（DDD）：按“教学域” 与“业务域” 划分数据模块，避免数据混杂：

教学域：存储“课程信息、实训任务、学生成绩、教学资源、教师操作记录”，如“课程表” 记录课程名称、授课教师、学期；“实训任务表” 记录任务名称、截止时间、评分标准；

业务域：存储“模拟客户数据、金融产品数据、学生实训方案、客户资产负债数据”，如“模拟客户表” 记录客户全维度信息；“实训方案表” 记录学生提交的方案内容、提交时间、批改状态。

数据分层与统计优化：采用“垂直分库+ 索引优化”，垂直分库区分“当前教学库”（存储本学期数据）与“历史归档库”（存储往期数据）；对教学高频查询字段（如“课程ID、实训任务ID、学生ID、批改状态”）建立组合索引，提升教师“批量查询学生成绩”“筛选未提交方案学生” 的速度（查询时间< 1 秒）。

学期归档策略：每学期结束后，系统自动将该学期的教学数据（课程、实训任务、成绩、学生方案）归档至历史库，当前库仅保留本学期数据，减少数据量；管理员可随时从历史库导出往期数据（如5 年前的实训成绩），用于教学质量分析或存档。

## 4.3 数据安全与性能优化：保障教学数据安全与实训体验
数据安全策略：

存储加密：采用透明数据加密（TDE）加密数据库文件，对学生学号、姓名、成绩等敏感字段采用AES-256 加密存储，即使数据库文件泄露，敏感数据也无法被破解；

动态数据屏蔽：教师查看班级成绩时，若未开启“显示学生姓名” 权限，系

  


统自动屏蔽学生姓名（显示为“学生XXX”），仅展示学号和成绩，保护学生隐私；

审计日志：记录所有数据变更操作（如“教师修改学生成绩”“管理员删除账号”），包含操作人、操作时间、操作内容、IP 地址，可追溯数据变更源头，保障数据不可篡改；

备份策略：支持“每日增量备份+ 每周全量备份”，备份文件存储在异地服务器（学校可指定备份地址），防止因硬件故障导致数据丢失。

性能优化措施：

分区表优化：对“ 学生实训方案表” 按“ 学期+ 课程” 分区（ 如 “2024-2025 学年1 学期《个人理财规划》” 为一个分区），查询时仅扫描目标分区，提升查询速度；

缓存优化：Redis 缓存“热门实训案例”“高频访问的金融产品数据”“教师常用的评分标准模板”，缓存有效期可配置（默认24 小时），减少数据库访问次数；

查询优化：对复杂教学统计（如“某课程各班级平均分对比”“某学生各实训任务得分趋势”）采用存储过程预处理，教师查询时直接调用预处理结果，统计时间< 3 秒。

页面响应时间：所有实训操作页面（如客户信息填写、财务计算、方案提交）响应时间< 2 秒，教学资源查看页面（如PPT、视频）响应时间< 1 秒；

数据查询响应时间：教师查询“班级成绩列表”“学生实训进度” 响应时间< 1 秒，查询“班级竞争力分析报告”“历史实训数据” 响应时间< 3 秒；

并发用户支持：支持至少500 名学生同时在线实训（含提交方案、查看资源、计算操作），10 名教师同时开展“任务创建、成绩批改” 操作，系统无卡顿、无数据丢失；

系统可用性：全年系统可用性≥99.9%，实训课程期间（ 如周一至周五

8:00-22:00）可用性≥99.99%，保障教学不受系统故障影响。



## 7.2 安全需求（符合学校数据规范）
数据传输加密：所有数据传输采用TLS 1.2 + 加密，防止数据在传输过程中被窃取或篡改；

数据存储加密：敏感数据（学生个人信息、成绩）采用AES-256 加密存储，数据库文件采用TDE 加密，保障数据存储安全；

安全审计：完整记录所有关键操作日志，日志保留时间≥1 年，支持审计追踪；

漏洞管理：开发团队每季度开展一次安全漏洞扫描，每年进行一次渗透测试，及时修复漏洞；提供“漏洞反馈通道”，学校发现漏洞可随时反馈，24 小时内响应修复。



## 7.3 可维护性（降低学校运维成本）
模块化设计：系统采用模块化开发，各功能模块独立部署、独立升级，如升级“财务计算引擎” 时不影响“实训任务管理” 模块，减少升级对教学的影响；

完整文档支持：提供“部署手册、运维手册、教师操作手册、学生实训指南、 API 文档”，文档包含详细步骤、截图、常见问题解答，学校IT 人员和教师可自主查阅解决问题；

自动化测试覆盖率：自动化测试覆盖率≥80%，保障系统升级和修复漏洞后

  


功能正常，减少人工测试成本；

容器化部署支持：支持Docker 容器化部署，学校可通过容器快速部署和迁移系统，简化部署流程，降低运维难度。

## 8.2 测试计划（保障系统质量）
  


单元测试：每个迭代阶段完成后，对核心模块（如财务计算引擎、规则引擎）开展单元测试，测试覆盖率≥80%，确保核心功能正确；

集成测试：第四迭代完成后开展集成测试，测试模块间交互（如实训任务创建→学生提交方案→教师批改成绩）是否正常，确保系统流程通畅；

性能测试：第五迭代阶段开展性能测试，模拟“500 用户并发实训”“10 教师同时批改成绩” 场景，测试系统响应时间、稳定性，确保满足性能需求；

安全测试：第五迭代阶段开展安全测试，包含漏洞扫描、渗透测试、数据加密测试，确保系统安全合规；

用户验收测试（UAT）：开发完成后，邀请学校教师和学生代表开展UAT 测试（1-2 周），收集使用反馈并优化（如调整界面操作流程、补充教学功能），确保系统贴合教学需求。
