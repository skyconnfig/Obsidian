# 现场抢答知识竞赛系统

```markdown
在线考试 / 竞赛抢答系统 — 完整开发需求文档
适用技术栈后端：SpringBoot3.0.5 + MyBatis-Plus + MySQL + Redis + Sa-Token管理后台：Vue3 + Vite + Naive UI + Pinia + Axios小程序端：uni-app + uview-plus3.6.29文档用途：需求说明、前后端分工、AI 生成代码依据格式：纯 Markdown、无代码、可直接复制使用
一、项目整体定位与核心功能说明
1.1 项目定位
一套前后端分离、支持实时竞赛与抢答机制的在线考试 / 比赛系统，面向多角色赛事场景，支持：
多角色协同：超级管理员、主持人、评委、选手、观众
完整赛事流程：题库管理 → 比赛创建 → 实时抢答 → 答题评分 → 大屏展示 → 成绩统计
支持客观题自动评分 + 主观题评委打分
实时数据同步、大屏投屏展示、赛事回溯与审计
1.2 核心功能总览
用户权限：多角色、可视化授权、批量导入导出、状态管理
题库管理：多题型、富媒体、导入导出、编辑审计
比赛管理：场次配置、计时策略、抢答模式、分值规则
实时抢答：时间戳判定、锁定机制、冲突处理
答题评分：实时推送、倒计时、自动 / 手动评分
实时大屏：分数排行、题目展示、动画提示
统计报表：正确率、成绩单、数据汇总
日志审计：全流程操作记录、不可篡改
系统配置：参数、备份、主题、多语言

id、权限标识、菜单 / 按钮权限、父级 ID
题目分类 / 标签表 question_tag
id、标签名称、类型、难度、时限
题目表 question
id、题干、题型、选项、答案、解析、分数、时长、标签、附件、创建人、编辑记录
比赛表 competition
id、名称、时间、状态、配置（计时 / 抢答 / 分值）
比赛场次表 round
id、比赛 ID、名称、题序、超时规则、抢答模式、权限控制
参赛表 participant
id、比赛 ID、用户 ID、队伍 ID、角色、状态
抢答表 rush_answer
id、场次 ID、题目 ID、用户 ID、时间戳、状态、锁定状态
答题记录表 answer_record
id、场次 ID、题目 ID、用户 ID、答案、得分、用时、状态
评分表 judge_score
id、场次 ID、题目 ID、选手 ID、评委 ID、分数、备注
分数排行榜表 rank
id、比赛 ID、用户 / 队伍 ID、总分、排名
操作日志表 operation_log
id、用户、模块、操作、内容、时间、IP

key、value、描述、状态

五、关键业务逻辑说明
5.1 用户与权限逻辑
多角色隔离：不同账号看到不同页面与功能
批量导入自动生成账号、密码默认规则
状态控制：禁用无法登录、锁定禁止操作
5.2 题库与题目逻辑
题型自动渲染界面、自动校验答案
附件自动预览：图片 / 音频 / 视频
编辑审计：记录修改人与修改时间
5.3 比赛与场次逻辑
一场比赛 = 多个场次
题序可固定可随机
超时自动提交、自动跳过
5.4 抢答核心逻辑
点击 → 记录时间戳 → 后端排序 → 返回第一
抢答成功立即全局锁定，防止重复
多人同时触发：按时间戳精确排序 + 随机兜底
支持个人抢答 / 队伍内抢答
5.5 答题与评分逻辑
客观题：提交 → 自动比对 → 立即出分
主观题：提交 → 评委打分 → 计入总分
分数实时入库、实时推大屏、实时更新排行
5.6 实时大屏逻辑
WebSocket 全双工推送
题目、倒计时、分数、抢答状态同步
抢答成功 / 失败动画提示、分数闪烁
5.7 日志与审计逻辑
所有关键操作自动记录
不可删除、仅管理员可查看
用于赛事回溯、争议判定
六、各端接口对接规则与数据流向说明
6.1 统一响应格式
json
{ "code": 200, "message": "成功", "data": {} }
6.2 状态码
200 成功
401 未登录 / Token 过期
403 无权限
400 参数错误
500 服务异常
6.3 认证规则
管理后台：Authorization: Bearer {token}
小程序：token 放入请求头
WebSocket 携带 token 鉴权
6.4 实时推送（核心）
协议：WebSocket
推送内容：题目、倒计时、分数、抢答结果、大屏数据
异常自动重连
6.5 数据流向
后台配置 → 发布比赛 → 小程序进入 → 实时推送 → 抢答 / 答题 → 评分 → 入库 → 大屏同步 → 统计生成
6.6 接口文档
集成 Knife4j 自动生成在线接口文档
```
