# **1. 项目目标与整体说明**

## 1.1 项目目标

在内网环境下实现一套 **低延迟（目标 <100ms）、高可靠、多人并发实时抢答** 的知识竞赛系统，支持：

* H5 / Android APK（选手端）
* Web 评委端 / 主持人端
* 大屏展示
* 后台管理（题库、场次、用户、统计）
* 实时通信：抢答、题目推送、计时器、分数更新
* 高拓展性：可支持校级、大型企业、线下活动

## 1.2 技术选型

| 模块 | 技术 |
| --- | --- |
| 前端 | **Vue 3 + Vite + TypeScript + Naive UI + Pinia** |
| 移动端 | **Flutter（推荐）** 或 Kotlin 原生 |
| 后端 | **Spring Boot 3 + Java 17 + MyBatis-Plus** |
| 鉴权 | Sa-Token |
| 数据库 | MySQL 8 |
| 缓存/消息 | Redis（抢答判定、高速队列） |
| 通信 | WebSocket / Socket.IO（推荐 Node.js 中间层） |
| 部署 | Linux + Nginx + Docker |
| 日志监控 | ELK 或 Loki + Prometheus + Grafana |

# **6. WebSocket / Socket.IO 实时通信协议**

## 6.1 命名空间

```plain
/ws/quiz
```

## 6.2 客户端 → 服务端事件

| 事件 | Payload |
| --- | --- |
| join\_session | {sessionId, teamId, token} |
| client\_buzz | {sessionId, questionId, teamId} |
| submit\_answer | {...} |
| ping | {} |

## 6.3 服务端 → 客户端事件

| 事件 | 描述 |
| --- | --- |
| session\_state | 当前场次状态 |
| question\_push | 推题 |
| buzz\_result | 所有队伍抢答顺序 |
| score\_update | 分数更新 |
| answer\_result | 答案评判结果 |
| error | 错误提示 |

# **7. 抢答判定流程**

## 7.1 Redis 数据结构

1. **Sorted Set：**`buzz:{sessionId}:{questionId}`
2. score = server\_timestamp

## 7.2 流程图

```plain
客户端抢答 → 后端接收 → 校验 token →
写入 Redis（ZADD） →
取最小时间戳 → 生成 buzz_result → 广播
```

# **11. 性能与安全策略**

## 性能

* WebSocket 广播 < 20ms
* Redis ZSET 抢答读写 < 1ms
* 单场次支持 >200 并发选手抢答

## 安全

* 全接口鉴权
* WebSocket 事件校验 token
* 防刷策略（IP 限流）
* 管理端敏感操作二次确认
