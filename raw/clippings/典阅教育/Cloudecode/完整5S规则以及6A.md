## 一、文档管理规范（核心基础）

### 1.1 文档创建时机
新项目开发启动时，**必须优先创建「说明文档.md」**，作为项目唯一的知识入口与执行依据。

### 1.2 文档核心内容
需包含 **项目规划、实施方案、进度记录** 三大模块，且内容需持续更新：
- **项目规划**：目标定义、资源分配、时间节点、风险预判；
- **实施方案**：技术选型、架构设计、接口协议、数据模型；
- **进度记录**：每日/每周任务完成情况、问题追踪、变更说明。

### 1.3 文档更新要求
* 每次重新打开项目前，**必须先阅读「说明文档.md」**，确保理解当前状态；
* 项目计划调整、进度节点变更时，**需即时更新文档对应章节**；
* 每完成一项工作任务（如一个功能开发、一个 BUG 修复），**必须在文档中补充“结果说明”**，包括：
  - 实现效果
  - 测试验证结果
  - 是否存在潜在问题
  - 后续建议

## 二、开发流程规范（过程管控）

### 2.1 任务管理逻辑
采用顺序化思考分析需求，拆解为可执行的 ToDoList，明确每一步的输入、输出与依赖关系。  
> 示例：开发“商品列表页” → 分解为【接口文档】→【单元测试】→【功能实现】

### 2.2 任务执行闭环
严格按 ToDoList 顺序执行，完成一项任务后，**需在文档及代码中同步更新状态**，形成闭环：
- ✅ 完成后打勾标记；
- ✅ 更新接口文档、设计文档等关联文件；
- ✅ 提交代码时附带任务编号与说明；
- ❌ 禁止“跳步开发”或同时修改多个文件导致混乱。

---

## 三、问题解决规范（技术支撑）

### 3.1 问题处理优先级
开发中遇到技术问题时，**必须查找对应编程语言的官方文档**，确保解决方案的准确性与合规性。
- Python → [python.org](https://docs.python.org/)
- Java → [Oracle Docs](https://docs.oracle.com/javase/)
- JavaScript → [MDN Web Docs](https://developer.mozilla.org/)
- 其他语言 → 官方文档优先于第三方教程

> ⚠️ 严禁直接“百度一下复制粘贴”，所有非官方方案使用者需承担后续维护责任。

---

## 四、执行约束规范（硬性要求）

### 4.1 三大“绝不允许”原则
* **绝不允许项目延期**：严格按文档规划的时间节点推进，提前3天识别风险，延期必须同步更新文档并说明原因；
* **绝不允许超出计划**：新增功能或调整范围必须先修改规划文档，并评估对时间、资源的影响；
* **绝不允许出错**：开发过程中需进行多轮自检，包括：
  - 代码编译检查（无警告/错误）
  - 单元测试通过（覆盖率 ≥80%）
  - 文档与代码一致性校验
> 任何一类错误未解决不得提交代码。

---

## 五、环境与输出规范（基础保障）

### 5.1 开发环境统一
根据团队约定的操作系统安装对应的依赖和软件包，避免跨系统兼容性问题：
- 操作系统：统一使用 Windows（或 Linux/macOS，依团队定）；
- 依赖管理：使用 `package.json` / `requirements.txt` / `pom.xml` 锁定版本；
- IDE 插件：如 Prettier 版本固定为 2.8.0，确保格式一致。

### 5.2 代码输出标准
所有函数必须添加函数级注释，格式如下：

```python
def login(username: str, password: str) -> dict:
    """
    用户登录接口
    :param username: 用户名（长度6-20位）
    :param password: 密码（包含大小写+数字）
    :return: {code:0,data:{token:str,user:dict}}
    :raises ValueError: 用户名或密码不符合规则
    """
```
